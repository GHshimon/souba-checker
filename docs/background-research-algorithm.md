# 相場の「背景」リサーチ・アルゴリズム設計

> 目的: 過去実績（数字）だけでなく **「なぜその相場になったのか＝価格変動の背景」** を、
> **視野を狭めずに** 調べられる仕組みを設計する。単純な経緯もレアケースも取りこぼさない。
> 最終更新: 2026-07-13 / 対象ブランチ: `claude/used-goods-tool-review-5w445h`

---

## 0. 何を作るか

「実績」= 相場の時系列（`sold_stats`。二層アーキ設計 §3）。
「背景」= **その変動の原因を推定し、根拠つきで複数シナリオとして提示する因果推定エンジン**。

出力は単一の答えではなく **シナリオカード**（主説＋対抗説＋レアケース＋未検証事項＋判断への含意）。

---

## 1. 設計原則（“視野・視点を大事にする”を仕組みで担保）

このツールの肝は精度より **視野**。以下5原則をアルゴリズムに埋め込む。

1. **単一解に畳まない** — 常に主説・対抗説・レアケースを併記。argmaxで1つに絞らない。
2. **視点の網羅を強制** — 「レンズ分類（§3）」を全カテゴリ必ず通す。思いつきの単一視点を排除。
3. **アーティファクト第一疑い** — 「見かけの変動（サンプル不足・状態ミックス・名寄せミス）」を
   **最初に疑う**。派手な物語を作る前に、単純なデータ要因で説明できないか確認（オッカム）。
4. **レアケースは期待値で拾う** — 低確率でも「当たると判断を覆す」要因（廃盤プレミア化・リコール）は
   `確率×影響` で別枠採点し、確率が低くても必ず提示。argmaxで捨てない。
5. **推測と証拠を峻別** — 全主張に `証拠あり(出典)/状況証拠/推測` のラベルと日付。
   証拠が無い仮説は confidence に上限を掛ける。「分からない」を正直に出す。

## 2. パイプライン（5フェーズ）

```
Phase 0 変動検知 ──▶ Phase 1 多視点仮説生成 ──▶ Phase 2 証拠収集
        │                    (レンズごとに並列)         (仮説ごとに並列)
        │                                                    │
        ▼                                                    ▼
   変動シェイプ分類                              Phase 3 反証・相互批判（時系列の向き/波及整合/アーティファクト代替）
                                                             │
                                                             ▼
                                          Phase 4 統合＝シナリオカード（複数保持）
```

### Phase 0 — 変動検知（Change Detection）
`sold_stats` 時系列から「本当に動いたか」と「動きの形」を出す。形が原因クラスを示唆する。

- 指標: 中央値の前期比 `Δ%`、トレーリング分布に対する `z`、変化点検知、
  **供給/需要シフト**（`Δactive_count`＝出品数, `Δsold_count_7d`＝売切数, `sell_through = sold_7d / active`）、
  **乖離**（新品↔中古 / チャネル間 / 状態ランク間）。
- **シェイプ分類**（→ §4 で原因クラスに対応）:
  `spike`(急騰急落) / `step`(段差・持続) / `drift`(緩やかな傾向) / `spread`(分散拡大＝状態や品質のばらつき) / `outlier`(単発)。
- **本物度** `confidence_real`: サンプル数・状態分布の安定・名寄せ健全性から算出。低ければ「アーティファクト濃厚」。

### Phase 1 — 多視点仮説生成（Multi-lens Hypotheses）
**レンズ分類（§3）の各カテゴリから独立に**候補原因を出す（＝視点の網羅を強制）。
Phase 0 のシェイプ＋タイミングをヒントに、各レンズが「この形ならこの原因があり得る」を列挙。
1視点が支配しないよう、**レンズごとに分離して生成**（実装は並列エージェント/並列プロンプト）。

### Phase 2 — 証拠収集（Evidence Retrieval, 仮説ごと）
各仮説に適した情報源から、**日付つき**で証拠を集める（§8）。
**因果の鍵は時系列の一致**＝「原因イベントが変動の“直前”にあるか」。

### Phase 3 — 反証・相互批判（Adversarial Cross-check）
各仮説を積極的に**棄却しにいく**。plausible-but-wrong を弾く。
- **時系列の向き**: 原因が結果より後なら **ハード棄却**（confidence=0）。
- **波及整合**: メディア要因なら関連商品も動くはず。単体だけなら別要因を疑う。
- **アーティファクト代替**: 単純なデータ要因（サンプル7件・状態ミックス変化）で説明できるなら、因果説を減点。

### Phase 4 — 統合（Synthesis, 複数シナリオ保持）
1つに畳まず、シナリオカード（§6）を出力。主説＋対抗説＋レアケース＋未検証＋判断含意。

## 3. レンズ分類（視点の全体像）— これが“視野”の背骨

| レンズ | 例（中古相場が動く理由） | よく出るシェイプ |
|--------|--------------------------|------------------|
| **需要・製品世代** | 後継機発表/発売で旧型下落、逆に名機化でプレミア | drift / step |
| **需要・話題性** | TV/YouTube/SNSバズ、有名人使用、ドラマ小道具、レトロ再評価 | spike |
| **需要・季節/イベント** | 新生活・クリスマス・アウトドア期・受験 | drift(周期) |
| **供給・希少化** | 生産終了/廃盤、限定、抽選販売、転売規制 | step(上) |
| **供給・放出** | 再販/復刻、在庫放出（倒産・閉店）、リコール返品 | step(下) / spike(下) |
| **制度・外部** | 為替（並行輸入）、法改正（技適・電波法・リサイクル）、サポート/OS終了、手数料改定 | step |
| **アーティファクト（見かけ）** | サンプル不足、外れ値、状態ミックス変化、相乗り/偽装出品、名寄せミス | outlier / spread |

> **アーティファクトを必ず1レンズとして常設**するのが最大の防御。数字のブレを因果と誤認しない。

---

## 4. シェイプ → 原因クラスの事前対応（生成のプライア）

| シェイプ | 第一に疑う原因クラス | 補足 |
|----------|----------------------|------|
| `spike` 急騰急落 | 話題性（メディア/SNS）/ 一時的供給ショック | 持続しにくい＝一過性の可能性大 |
| `step` 段差・持続 | 供給（廃盤/再販）/ 制度（規制・サポート終了） | 構造変化＝相場が定着しやすい |
| `drift` 緩やか | 製品世代交代 / 季節性 | 方向とトレンド継続性を見る |
| `spread` 分散拡大 | 状態ミックス変化 / 名寄せ崩れ / 品質ばらつき | **アーティファクト濃厚** |
| `outlier` 単発 | サンプル不足 / 外れ値 | まず無視 or 母数確保待ち |

## 5. スコアリング（透明な加点式）

### 5.1 仮説の確からしさ `confidence ∈ [0,1]`
各要素を[0,1]に正規化して加減算（重みは調整可）:

```
confidence = clamp( wT·T + wS·S + wP·P − wA·A − wR·R )

  T 時系列一致度   原因イベントが変動の直前ほど高い（後なら 0＝棄却）
  S 証拠の強さ     一次ソース/複数独立ソースほど高い（推測のみは低)
  P 波及整合性     関連商品・チャネルの動きが仮説と整合
  A アーティファクト代替可能性  データ要因で説明できてしまう度合い（減点）
  R 反証の強さ     積極反証がどれだけ効いたか（減点）

  例の重み: wT .30, wS .30, wP .20, wA .20, wR .20
  ハードゲート: 因果の向きが逆（原因が結果より後）→ confidence = 0
  上限: 証拠が「推測」のみ → confidence ≤ 0.4
```

### 5.2 レアケースを拾う `decision_value`（“視野”の担保）
argmax（最有力だけ）だと重大な低確率要因を捨ててしまう。**期待値**で別枠採点:

```
decision_value = probability × impact_if_true
  impact_if_true = 「この背景が本当なら判断が覆るか」の大きさ
                   （買い→見送り / 見送り→仕込むべき の反転度）

  → confidence が低くても decision_value が高ければ「レアケース候補」として必ず提示
```

### 5.3 相場の持続性 `persistence`（今動くか待つか、に直結）
`shape × cause_class` から一時的/構造的を推定。
例: `step×供給(廃盤)` = 構造的（継続）／ `spike×話題性` = 一時的（戻る）／ `drift×世代交代` = 構造的だが下方向。

## 7. アルゴリズム擬似コード

```ts
function researchBackground(matchKey): ScenarioCard {
  const series = loadSoldStats(matchKey);            // 二層アーキの sold_stats
  const change = detectChange(series);               // Phase 0: shape / Δ / 供給需要 / confidence_real
  if (change.confidence_real < 0.4)                  // まずアーティファクトを疑う
    return artifactDominant(change);

  // Phase 1: レンズごとに独立生成（並列）— 視点の網羅を強制
  const hyps = LENSES.flatMap(lens => generateHypotheses(lens, change));

  // Phase 2 & 3: 仮説ごとに証拠収集→反証（並列）
  const scored = hyps.map(h => {
    const ev = gatherEvidence(h, change.window);     // 日付つき・情報源つき
    const refute = crossCheck(h, ev, change, series);// 時系列の向き/波及/アーティファクト
    return score(h, ev, refute);                     // §5.1 confidence + §5.2 decision_value
  });

  // Phase 4: 畳まずに構成
  return synthesize({
    primary:      topByConfidence(scored),
    alternatives: nextByConfidence(scored, 2),
    rareCases:    byDecisionValue(scored),           // 確率低でも影響大は拾う（§5.2）
    artifact:     change.artifactNote,
    unknowns:     collectUnknowns(scored),
    checklist:    completenessCritic(scored, LENSES) // §9 の自己点検
  });
}
```

多視点生成（Phase1）と 仮説ごとの証拠収集・反証（Phase2/3）は**並列**が自然。
個人利用ツールなら、収集ワーカー（レイヤーB）の1ジョブ、または `/api/research` が Gemini を
複数回オーケストレーションする形で実装できる（既存 `/api/similar` と同じ構造化JSONパターン）。

## 9. 幻覚対策・品質（“視野”を守る自己点検）

- **証拠は必ず実データ/実検索から**。LLMの役割は「時系列の突合とランク付け・物語化」であり、原因の**捏造をさせない**。
- 全主張に `証拠あり/状況証拠/推測` ラベル＋日付。推測のみは confidence 上限。
- **完全性クリティック**（Phase4末尾）が毎回チェック:
  「全レンズ検討したか / アーティファクトを排除したか / レアケースを1つ以上出したか /
  因果の向きを確認したか / 推測と証拠を分けたか」。未達なら不足を `unknowns`＋`next_actions` に。
- **鮮度**: `collected_at` を持ち、古いカードは「要再調査」に降格。

## 10. UI 統合

- **ProductCard / Insights** に「背景リサーチ」パネルを追加:
  - 上段: 変動の**タイムライン**（相場曲線に原因イベントのピンを重ねる）。
  - 中段: **シナリオカード**（主説を大きく、対抗説・レアケースを折りたたみ）。confidence をバッジ表示。
  - 下段: **判断への含意**（今買う/待つ/様子見）＋ persistence（一時的/構造的）＋ 次アクション。
- 上限仕入れ値（`profit.ts`）と接続: 「構造的な上昇」なら想定売価の採用レンジを引上げ、
  「一時的バズ」なら**割り引いて**上限を保守的に。背景が数字の使い方を変える。

## 11. 段階導入ロードマップ

| # | やること | データ要件 | 効果 |
|---|----------|-----------|------|

> **アーティファクト排除と単純な経緯の説明**を固めるのが、視野を保つ最短路。
